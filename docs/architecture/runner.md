# Runner protocol

Runner initiates outbound HTTPS connections only. Registration consumes a hashed, single-use ten-minute enrollment token and issues a revocable tenant/repository-scoped opaque credential, hashed server-side and returned exactly once. `POST /runner/registrations` takes the enrollment token and capabilities; `POST /runner/heartbeats` authenticates with `Authorization: Bearer <credential>`. Incompatible protocol or schema versions are refused with 409 before any state change, request bodies are schema validated and size capped, and responses carry an error code only: no internal diagnostics reach an unauthenticated caller. Local secrets use restrictive permissions or container secrets.

Heartbeat every 30 seconds, offline after 90; heartbeat does not renew a job. Leases last 120 seconds, renew every 30, carry attempt identity and monotonically increasing fencing token. Lease liveness is decided by the database clock alone, and claim and renewal report the remaining time (`expiresInMs`) as well as a timestamp, so neither the control plane nor a remote runner has to agree with another machine's clock; a timestamp compared against a local clock would let a lease the database already expired and reassigned still be honoured. `POST /runner/leases` claims one job or answers 204 when idle, `POST /runner/leases/:leaseId/renewal` extends it, and `POST /runner/leases/:leaseId/failure` returns an attempt to the queue or ends it. Failed renewal is the cancellation signal: a cancelled, revoked, superseded or expired lease answers 409, and the runner aborts the job. A runner survives a partition only while the lease it already holds is still valid; past that margin it must assume the lease is gone. A lost lease reports neither a result nor a failure, because the fence it holds is stale and another runner now owns the work. Stop and clean up on lease loss/cancellation/revocation, including discarding the job-scoped GitHub credential. Retry infrastructure failures at most three execution attempts; incompatible models/configs do not retry.

Lease contains immutable review snapshot, capability/schema versions and a single-repository Contents-read GitHub token. That token is issued by `POST /runner/leases/:leaseId/token`, which resolves the lease under the renewal liveness conditions before reaching the issuer, so a revoked runner, superseded fence, expired or released lease, terminal run, disabled repository or suspended installation is refused with 409 and no credential is minted. GitHub installation tokens last up to one hour and cannot be revoked individually, so a runner must discard its token as soon as it loses a lease; refusing to issue is the control-plane half of that contract. No cloud provider credential or database access. Refresh tokens only for active authorized leases. Execute shared scanner/extractors/retrieval/review/suggestions with local Ollama. Initial and incremental scans use runner too. Indexed derived-data uploads require explicit retention opt-in; ephemeral context is rebuilt.

Result submission validates tenant, runner, lease, attempt, head, snapshot digest, extractor versions and result digest. Digests are versioned canonical digests (`domainDigest` in `@humanize/domain`, prefix `humanize-digest-1`): the payload is schema-normalized, then encoded with code-unit key ordering so that a PostgreSQL JSONB round trip, a parsed wire payload and an in-memory value all agree. `JSON.stringify` is not a digest; key order is not stable across JSONB storage and schema parsing. Changing the digest version invalidates in-flight leases and must be treated as a protocol change. Duplicate identical uploads are idempotent; conflicting duplicates rejected. A lease that already received a result still resolves for a further submission, so a runner whose response was lost to a partition receives the same idempotent answer instead of lease loss. Before anything is stored, the control plane independently validates the envelope against the lease snapshot: nodes pinned to the reviewed head SHA and repository, no duplicate node or evidence identities, candidates and evidence referencing only submitted material, and every quoted fragment actually present in the node it points at, so a fabricated quote cannot reach a pull request. Violations return codes only and leave the lease open for a correct submission; the payload is never echoed back. Control plane independently revalidates source/evidence/patches through transient GitHub reads and publishes; no cloud model calls during validation.

Reject incompatible protocol major or required schema/capability hashes before checkout. Ship non-root image/CLI, read-only root, bounded temporary workspace, no Docker socket. Distinguish container localhost from host networking. Logs contain IDs/timing/counts/error classes only.
