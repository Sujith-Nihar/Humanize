## Completion evidence

- Last updated: 2026-09-20T21:31:27.714356+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Restricted Git acquisition ran against a REAL private GitHub repository for the first time, authenticated with an installation token minted by GitHubTokenBroker. Proven live: the repository refuses an anonymous clone once credential helpers are disabled exactly as git.ts disables them, so the credential path is genuinely exercised rather than bypassed by public access; GitRepository.acquire then clones it successfully (7 of 7 clone-only runs). Defect found and fixed in the quota monitor: it mapped every assertQuota failure to WORKSPACE_LIMIT and SIGKILLed Git, so a transient ENOENT from the measurement corrupted the object database. The monitor now kills only on a genuine quota breach. pnpm check passed with 219 unit tests across 33 files.
- Next action / remaining acceptance: SEPARATE DEFECT, OPEN: tree() runs ls-tree -r -l, and -l forces Git to resolve every blob size. On a --filter=blob:none clone that triggers a lazy fetch of every blob, which defeats the point of the blobless clone and fails intermittently with a non-zero exit and EMPTY stderr (observed failing on 5 consecutive runs, then succeeding on others). Needs a size strategy that does not fetch blob content, for example cat-file --batch-check over candidate paths only. Related: stderr is discarded entirely so an operator cannot diagnose a Git failure at all; a classified error channel is needed that never echoes raw stderr. Also still absent: live missing-history handling and exhaustive argument-injection cases.
