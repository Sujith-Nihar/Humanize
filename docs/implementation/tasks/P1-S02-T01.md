## Completion evidence

- Last updated: 2026-09-20T21:45:01.934204+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Restricted Git acquisition verified against a REAL private GitHub repository using an installation token minted by GitHubTokenBroker. The repository refuses an anonymous clone once credential helpers are disabled the way git.ts disables them, so the credential path is genuinely exercised rather than bypassed by public access. TWO DEFECTS FOUND BY FIRST LIVE USE, BOTH FIXED. (1) The quota monitor converted every assertQuota failure into WORKSPACE_LIMIT and SIGKILLed Git mid-write; a transient ENOENT from measuring a directory Git was writing left a commit graph referencing objects absent from the object database, so a later command failed as repository corruption. It now kills only on a genuine quota breach. (2) tree() used ls-tree -r -l, and resolving a size means having the blob, so on a --filter=blob:none clone it lazily fetched the ENTIRE repository: measured 104 KiB growing to 17 MiB, with the first call against a fresh clone exiting non-zero. Sizes are no longer listed; a size is known only when a blob is read, where blob() enforces the cap for that one file. MEASURED AFTER THE FIX against the live private repository: after clone 0.03 MiB, after tree() 0.03 MiB (no growth, so nothing was fetched to list), after reading all supported content 0.12 MiB, versus 17 MiB before. 3 of 3 runs succeeded where 5 of 5 previously failed. pnpm check passed with 220 unit tests across 33 files.
- Next action / remaining acceptance: Live missing-history handling and exhaustive argument-injection cases are still absent. Git stderr is discarded entirely, which is deliberate so a malicious path or credential-bearing diagnostic cannot leak, but it left both defects above undiagnosable from the outside: every failure looked identical. A classified error channel that distinguishes causes without echoing raw stderr is the next thing this module needs.
