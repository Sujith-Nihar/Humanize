- Evidence: Ollama adapter implemented against the native /api/chat endpoint with the JSON schema in the format field, temperature 0, local-only enforcement, model availability checked before each request, cloud and remote-host models filtered out of listModels, and an optional /api/embed path. FINDING AND FIX (2026-09-18): the adapter set num_predict but never num_ctx. Ollama defaults to a small context window (commonly 4096) and silently discards the overflow, and chat truncation drops the oldest messages first, which is the system prompt. The untrusted-content boundary declaration could therefore be evicted while the repository text it governs survived, degrading output quality and weakening the prompt-injection boundary at the same time. The adapter now requests num_ctx covering the whole budgeted request (LIMITS.contextTokens + LIMITS.outputTokens = 16000, raisable through AdapterOptions.contextTokens), with a test asserting num_ctx is at least the full budget, num_predict never exceeds it, and temperature stays 0. Results: pnpm check passed with 111 unit tests across 20 files; pnpm build passed.
- Next action / remaining acceptance: Still unverified against a live service: no Ollama server has been contacted, so no model has been shown to satisfy the reviewer and verifier schemas in practice. A gated live contract test and the capability probe (P1-S04-T07) are the next step. A selected model must support a context window of at least 16000 tokens, otherwise the model clamps num_ctx and the silent truncation returns.
