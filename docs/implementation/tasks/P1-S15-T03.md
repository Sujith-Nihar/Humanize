- Implementation revision: current working tree; no commit claimed.
- Evidence: Runner packaged and documented, and the image was built and exercised rather than merely written. docker/runner holds a multi-stage Dockerfile, a reference compose deployment and a deployment runbook at docs/runbooks/runner-deployment.md covering enrollment, upgrade, revocation and failure symptoms. VERIFIED BY RUNNING THE IMAGE, not by reading it: the process runs as uid 10001 with no exposed ports, the root filesystem is read-only and /app is unwritable by the runner, git 2.39.5 is present as the only external binary, the image is 117 MB, it refuses to start without its two required variables, and it reaches a real Ollama on the host across host.docker.internal and reports models:1 at startup. THREE DEFECTS FOUND BY RUNNING IT. First, the tmpfs workspace was owned by root and therefore unwritable by the unprivileged runner, so no workspace could be created and no review could run; the mount now carries uid and gid, which is also called out in the runbook because a hand-written deployment would hit the same wall. Second, the image could not resolve @humanize packages at all, because a pnpm workspace keeps its links in each package node_modules which the build context excludes; the build now uses pnpm deploy to produce a self-contained tree, which also cut the image from 207 MB to 117 MB. Third, an unreachable model killed the process with a raw TypeError fetch failed from Node internals; startup now checks the model endpoint and exits with a sentence naming the endpoint and what to do, and separately reports when no model is installed. A startup line was added because silence and a crash loop look identical to an operator. Results: pnpm check 200 unit tests across 33 files; pnpm build passed; 70 integration tests passed.
- Next action / remaining acceptance: Not yet proven: upgrade on a clean host, since the image has only been built and run locally and never published or pulled; and the compose deployment has not been run end to end against a real control plane, which needs GitHub App credentials. The healthcheck is a placeholder that always succeeds rather than reporting whether the runner holds a lease or can still reach its model. No image signing, SBOM or vulnerability scan is in place, which P1-S20 should cover before distribution.
