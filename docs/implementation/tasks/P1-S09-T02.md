## Completion evidence

- Last updated: 2026-09-18T16:55:04.748863+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: JSON and YAML localization extraction implemented. A file is treated as a locale resource only when its path follows convention (locales, i18n, translations, messages, lang, or a language-coded filename) or configuration declares it, so arbitrary JSON such as package.json or tsconfig.json is never reviewed as prose; a non-locale data file now returns a NOT_A_LOCALE_SOURCE diagnostic rather than silently extracting nothing, because silence is the dangerous case. Values are reviewed and keys are context only. Machine values are excluded by key and by shape: URLs, paths, colours, endpoints, identifiers, numbers and values containing no letters. Source spans map to the value inside its quotes so a replacement re-encodes in place, quote style is recorded, nested objects and arrays are walked, placeholders survive extraction, and an escaped value is marked unsafe for verbatim replacement. YAML is supported through the same path. 9 unit tests cover locale discrimination both ways, key-versus-value handling, machine value exclusion, exact spans, nesting, YAML with ICU and handlebars placeholders, escape safety, the diagnostic for a non-locale file, and malformed input. MEASURED EFFECT: locales/en.json in the fixture corpus now produces an approved_voice finding on "Unlock unprecedented potential today", which the previous run could not see at all. Results: pnpm check 153 unit tests across 27 files.
