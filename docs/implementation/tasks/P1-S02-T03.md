## Completion evidence

- Last updated: 2026-09-20T21:45:01.960724+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Classification is now two-stage, which live use proved necessary. The runner previously read every tracked blob in order to classify it, which on a blobless clone fetches every file in the repository including the binaries the classifier is about to reject. A path-only classification pass now runs first, content is fetched only for files that survive it, and the entry is then re-classified with its bytes so a binary or generated file with a reviewable path is still caught. InventoryEntry.size and TreeEntry.size are optional, because a size is unknown until a blob is read, and classify no longer judges TOO_LARGE on an unknown size. Verified against the live private repository: 90 tracked blobs, 17 files yielding content, 122 ContentNodes extracted, total fetch 0.12 MiB.
- Next action / remaining acceptance: Inventory still has no live coverage for submodules, symlinks or special paths in a real repository, and no test asserts that a binary file with a reviewable extension is rejected only after its content is read.
