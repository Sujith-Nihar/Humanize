## Completion evidence

- Last updated: 2026-09-18T19:26:13.348001+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Result upload, independent validation and the runner seam are implemented, and asynchronous publication is now possible. validateRunnerResult treats the runner as untrusted and checks nodes pinned to the reviewed head and repository, duplicate identities, candidates referencing only submitted nodes, quoted text genuinely present in its node so a fabricated quote cannot reach a pull request, resolving evidence references, and verification verdicts bound to a recomputed candidate identity. The upload route refuses oversized bodies before parsing, malformed or misaddressed envelopes, invalid content with codes only, and stale, superseded, expired, foreign or conflicting submissions, with identical duplicates idempotent and validation running before anything is persisted. Acceptance schedules publication through a port rather than publishing inline, and a duplicate never schedules twice. ARCHITECTURE CONFLICT SURFACED AND RESOLVED AS ADR-038: a scheduled publication was impossible to act on, because findings cannot be persisted with their text in ephemeral retention mode and the accepted result existed only in the answered HTTP request. Inline publication would make a runner wait on GitHub and lose the review on failure; an in-memory handoff would not survive a restart or a second instance. The accepted resolution introduces publication_payloads, holding the validated payload only until publication completes or is abandoned, which matches the specification wording that ephemeral context is rebuilt per review and DELETED AFTER THE JOB rather than never written. Migration 0004_famous_fixer.sql applies from a clean disposable database, and five PostgreSQL tests prove the lifetime guarantee: discarded after success, discarded after abandonment, swept when a crash leaves one behind while a live payload is untouched, refused for a non-existent run, and isolated by tenant. Results: pnpm check 191 unit tests across 31 files; pnpm build passed; 51 integration tests passed from a freshly created disposable database.
- Next action / remaining acceptance: No publish worker process exists yet, so the payload lifetime is enforced by the store and proven at that level but not yet by a worker that calls discard on every path, including after an abandoned publish. That worker, its queue subscriptions and the retention sweep schedule are the next step, and the GitHub transport it drives still needs App credentials.
