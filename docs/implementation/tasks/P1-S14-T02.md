- Evidence: GitHub publisher implemented in packages/github/src/publisher.ts. It renders a grouped COMMENT review, never APPROVE or REQUEST_CHANGES, with inline comments placed only on right-hand-side lines the pull request actually added and that are representable in the diff; a finding whose line is not part of the diff moves to the summary rather than being attached to an unrelated line the author did not touch. Each comment carries a stable fingerprint marker and the review body a review marker, so a re-review can update rather than duplicate. The summary states how much changed content was reviewed, collapses budgeted-out findings into a details block, and says plainly when there is nothing to flag. Check conclusions follow the specification and ADR-017: success with no findings, neutral for advisory findings however severe, and failure only when a customer-configured deterministic blocking rule is violated, so subjective wording can never fail a build. A native suggestion block is rendered when a safe replacement exists, which needs no Contents write permission. 7 unit tests cover exact-line placement, the summary fallback for undiffed lines and missing files, the collapsed section, the empty case, suggestion rendering, the check conclusion matrix, and an assertion that nothing published ever claims machine authorship (INV-006). Results: pnpm check 134 unit tests across 23 files; pnpm build passed.
