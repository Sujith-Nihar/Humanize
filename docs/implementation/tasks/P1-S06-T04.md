## Completion evidence

- Last updated: 2026-09-18T18:41:41.340233+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Installation, repository and pull-request event handling implemented in apps/worker/src/handlers.ts, with the acceptance property proven: reordered events cannot revive removed access or obsolete work. An installation event records suspension and deletion, and DELETION IS TERMINAL: the update only ever moves deleted from false to true, so a redelivered creation cannot restore access a user removed, and suspension is not touched once an installation is deleted. A repository is recorded on any event that carries one, but a repository nobody enabled is never reviewed. A pull request is only scheduled for review on opened, synchronize, reopened or ready_for_review, drafts are skipped unless marked ready, and the generation advances only when the head actually moves so a redelivery is inert. ORDERING DEFECT FOUND AND CLOSED: the event contract carried no timestamp, so a redelivered older event would have overwritten a newer head. GitHubEventSchema now carries occurredAt, normalizeWebhook takes it from the pull request or repository updated_at and falls back to receipt time, and the pull-request upsert refuses to apply an event older than the row it would overwrite, returning superseded_by_newer_event. 5 PostgreSQL integration tests prove each property, including that a stale synchronize cannot drag a pull request back to a head it has moved past, and that a redelivered creation cannot undelete an installation. Results: pnpm check 191 unit tests across 31 files; pnpm build passed; 45 integration tests passed from a freshly created disposable database.
- Next action / remaining acceptance: The handler decides what should happen but does not yet enqueue: a scheduled review returns its intent rather than creating a review run and sending pull_request.review, because run creation needs the resolved configuration snapshot that P1-S08-T01 produces and nothing yet reads .humanize.yml from the base commit. Debounce across rapid pushes is represented by the generation counter but no coalescing window exists. The worker process itself is still a library rather than a running service with queue subscriptions.
