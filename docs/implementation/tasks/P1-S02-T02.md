## Completion evidence

- Last updated: 2026-09-20T21:31:14.978394+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: First live acquisition against a real private GitHub repository exposed a defect in directoryBytes. It walked the workspace while Git was writing lazy-fetch packfiles, so an entry named by readdir was routinely gone before lstat reached it; measured ENOENT on objects/pack/tmp_pack_k3U8yJ and objects/pack/tmp_idx_UBKkKk. The quota monitor in git.ts converted ANY assertQuota failure into WORKSPACE_LIMIT and SIGKILLed Git mid-write, which left a commit graph referencing objects absent from the object database, so a later command died with "This is probably due to repo corruption". Fixed: directoryBytes skips vanished entries (ENOENT, ENOTDIR) rather than throwing, since a file that no longer exists contributes no bytes. Regression value proven: reverting directoryBytes makes the new churn test fail with exactly that ENOENT, and the fix makes it pass. A second test asserts a genuine quota breach is still reported. Live loop against the private repository went from 5 of 5 failing to zero WORKSPACE_LIMIT failures. pnpm check passed: 219 unit tests across 33 files, plus docs, boundaries, typecheck and lint.
- Next action / remaining acceptance: Workspace cleanup on cancellation, timeout and orphan recovery still lack live coverage. The quota check is also unbounded in cost: it rescans the whole workspace every 500 milliseconds regardless of size, which will not hold for a large repository and should become incremental or sampled.
