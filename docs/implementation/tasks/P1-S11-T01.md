## Completion evidence

- Last updated: 2026-09-18T17:06:42.378984+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Source-specific replacement encoders implemented in packages/suggestions/src/encode.ts. JSX and Markdown text is emitted verbatim after refusing prose carrying markup; HTML text is entity-encoded; HTML attribute values are encoded for the quote style actually used, so a quote inside the replacement becomes an entity and cannot terminate the attribute or introduce a new one; JSON and locale values are re-encoded inside their existing quotes with escapes; bare YAML scalars are refused when the replacement starts with an indicator character or would read as a mapping; JavaScript and TypeScript string literals are escaped for single, double or template quoting including dollar-brace sequences. A node the extractor marked unsafe, a control character, a multi-line replacement for a single-line node and an unsupported source kind are all refused rather than guessed, because a wrong encoding corrupts a customer file. Tests cover JSX text, HTML text and attributes, locale values with embedded quotes, and the refusal cases. Results: pnpm check 173 unit tests across 29 files; pnpm build passed; 40 integration tests passed.
- Next action / remaining acceptance: Vue, Svelte and CSS encoders are absent because their extractors do not exist yet (P1-S10). Multi-line and complex Markdown nodes containing inline links or emphasis remain comment-only, as the specification requires until a dedicated validator proves such a patch safe.
