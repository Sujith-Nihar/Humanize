- Evidence: Stage 1 live acceptance MEASURED AND NOT MET on llama3.2 (Apple M3, 16 GB, 2026-09-28). Batched run of 12 gold nodes: 164.1 s, one reviewer call, zero model candidates. Repeat: the batch call hit the 180 s adapter cap (TIMEOUT) and fell back to 12 single calls of 23-99 s each. Root cause is output generation, not round trips: llama3.2 decodes at 12-14 tokens/s on this machine with or without a JSON schema and at 4096 or 16000 context, and the reviewer emits 250-1157 output tokens per node. In one raw response about 600 of 783 output tokens were ten copied evidence citations, each a 64-character hex id plus a repeated quote, on a case labelled clean; the verifier likewise echoes 64-character candidate ids. At this decode rate the two-minute target allows roughly 115 output tokens per node. DEFECT FOUND AND FIXED: the batch packer estimated tokens at 4 characters each, but rendered prompts measured 2.4-3.0 characters per token (hex ids tokenize badly); the 12-node batch was 13,886 real tokens against an estimate of 10,545, so it was sent as one call beyond the 12,000 input budget, and with 4,000 output tokens beyond the 16,000 Ollama window. The estimator is now 2 characters per token, and a test bounds every batched prompt against the measured 2.4 ratio independently of the estimator (verified to fail with the old estimator). pnpm check exit 0, 376 tests.
