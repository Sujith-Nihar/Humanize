## Completion evidence

- Last updated: 2026-09-18T17:14:30.878866+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Extraction release gate implemented in evals/extraction. A labelled corpus in gold.ts states, per parser, the user-visible strings extraction must find and the machine strings it must never mistake for prose (endpoints, identifiers, asset paths, class lists, colours, code fences, script and style contents). gate.test.ts computes precision, recall and range accuracy per parser and enforces the specification thresholds of 98%, 90% and 99%, failing the default test lane when any parser falls below them; a second test asserts no labelled machine string is ever extracted, because noise about text the author never wrote for a reader is worse than a missed string. Range accuracy is measured PER SEGMENT rather than per node: a Markdown paragraph containing an inline link assembles its text from several source runs, so each segment must map its slice of the text back to the exact source it came from. MEASURED: babel, markdown, html, json-locale, vue, svelte and css all at precision 100%, recall 100%, range accuracy 100%. The gate earned its place on its first run by rejecting a mislabelled fixture and an over-strict metric. Results: pnpm check 183 unit tests across 31 files.
- Next action / remaining acceptance: The corpus is small, with one file per parser, so 100% means the gate passes on these cases rather than that extraction is perfect; the specification expects hundreds of fixtures and the corpus must grow substantially before the numbers carry release weight.
