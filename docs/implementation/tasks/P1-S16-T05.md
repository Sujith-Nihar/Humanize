Enrollment exists only as a store method with no HTTP route, so a customer cannot be onboarded without direct database access, and there is no way to see or revoke a runner through the product. Two gaps found while reading the current code: runner_enrollments records no author, although minting a runner credential is a privileged act that should carry provenance, and nothing lets an administrator cancel an enrollment created by mistake before it is used.
- Next action / remaining acceptance: In progress this exchange. Scope: a migration adding created_by to runner_enrollments; store methods to create an enrollment with the administrator check performed inside the same transaction as the write, to list enrollments and runners without ever exposing a token or credential, to cancel an unconsumed enrollment, and to report runner online state from the heartbeat; and authorized HTTP routes for each. Properties to prove: the token is returned exactly once and never readable afterwards, a member who is not an administrator of the named repositories cannot mint one, a repository outside the organization or not enabled is refused, cancelling an unconsumed enrollment prevents registration, and a consumed enrollment cannot be cancelled retroactively to imply it was never used.
