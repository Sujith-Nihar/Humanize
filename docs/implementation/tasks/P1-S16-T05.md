## Completion evidence

- Last updated: 2026-09-29T22:34:05.061871+00:00.
- Implementation revision: current working tree; no commit claimed.
- Evidence: Runner enrollment and status administration implemented, removing the manual database step that blocked customer onboarding. Migration 0007 adds created_by and revoked_at to runner_enrollments, because minting a runner credential is a privileged act that must carry provenance and an administrator must be able to cancel an invitation created by mistake. RunnerStore.enrollment now takes the author and an administrator check performed INSIDE the transaction with the repository rows held, so rights cannot lapse between the check and the write; a partial grant is refused outright rather than narrowing the scope, because silently issuing a narrower credential would not be what the caller authorised. Registration additionally refuses a revoked invitation. New store methods list enrollments and runners without ever returning a token, hash or credential, report runner liveness from the heartbeat measured by the DATABASE clock with a 90-second offline threshold, and cancel only a pending invitation. Authorized routes expose all of it: POST and GET /api/runner/enrollments, DELETE /api/runner/enrollments/:id, GET /api/runners and DELETE /api/runners/:id. The token is returned exactly once on creation and never appears in a listing. The author is taken from the session and never from the request body. FOUR PROPERTIES PROVEN BY TEST: a used invitation cannot be cancelled retroactively so it cannot be made to look unused, a revoked invitation is no longer redeemable, a stale heartbeat reads as offline and a revoked runner as neither online nor live, and every route refuses another organization with 403 while the store is never called. 4 PostgreSQL tests and 3 route tests. Results: pnpm check 385 unit tests across 47 files; pnpm build passed; 74 integration tests passed from a clean disposable database with migrations 0000-0007 applying from scratch.
- Next action / remaining acceptance: The administrator check is an injected port with no production implementation, so nothing resolves real GitHub repository administrators yet; until that exists a signed-in member of the organization can mint an enrollment, which is weaker than the task intends. No dashboard page calls these routes, so onboarding is now possible over HTTP but still has no interface. Enrollment creation has no rate limit, so a compromised session could mint invitations repeatedly; each is still single-use, short-lived and scoped, but the adversarial review already recorded the absence of rate limiting as an open item.
